# gRPC Adapter

A client application has to implement code to call the methods defined in the services. The services are defined within the Protobuf (*.proto) files next to this documentation. A service contains definitions for methods with parameters and return values that can be remotely called. In order to implement the code that consumes these services each proto file has to be translated into the programming language the client is written in using a protobuf compiler. Follow the instructions described here. Referencing a proto file in a .NET Project enables you to generate the C# assets that represent the messages defined in the proto file. Clients generated that way can be used to call the methods provided by Continuous Testing. C++ classes and header files can be generated by using Protoc with provided proto files.

## Supported Features

- Start/Stop recording

- Set custom name for future identification of subsequent recordings/evaluations

- Set values of recorder documentation attributes

- Subscribe to system events

- Read out and set processing variables defined in the processing specification

- Subscribe to states of conTEST and the connected hardware

- Subscribe to evaluation results

- Read out configured profiles and set the currently used profile

- Read out available 1D/2D analyses and subscribe to them

- Subscribe to condition monitoring

- Control Live Monitoring
